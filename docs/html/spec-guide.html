1. Why this exists

Planning teams look data-rich and stay context-poor. Systems become export warehouses. Judgment and overrides die in spreadsheets and chat. Agents amplify the mess unless the unit of work is forced into a durable shape.

The Analysis Package is that unit: what was read, what was run, what a human changed and why, what was delivered, and whether it passed the gate - portable enough to leave the laptop.

Sibling essays: token capital dies in Excel; do not buy the middle first; four buckets of context; promote only what survived Monday. This spec is the operational contract those ideas demand of every agent–planner pair.

2. What it is

Formal interchange contract. Every planning agent that pair-codes or pair-plans with a human planner MUST emit and consume work in Analysis Package form for each bounded cycle. Humans remain accountable for judgment. The package is how that judgment becomes auditable, replayable, and - under policy - trainable token capital.

Agents must

Produce valid packages; refuse “done” when the completeness gate fails.

Planners must

Own overrides, truths, judgments, and sign-off - not leave meaning only in cells or chat.

Leads must

Version guidelines, reason codes, ontologies; run validators and gold packs.

Downstream may

Trust only package contents and declared contracts - never tribal side channels.

3. Design goals (non-negotiable)

GoalMeaning
Portable Self-contained directory (YAML authoring → RO-Crate). Moves across laptops, repos, and orgs without the original chat session or suite license.
Deterministic core Pinned inputs + method + engine versions + recorded overrides regenerate stable engine outputs within tolerances. Models cannot be silent math.
Extensible Validators enforce the MUST set only. New logic lives in code/ + guideline bumps and pack-type profiles - not forks of the core contract.
Universal fit Process-shaped, not domain-shaped. Any planning process that can name outputs, inputs, method, and overrides can comply. No single BOM/ERP religion.

4. Universal fit test

The contract is this shape:

outputs (contract + consumers) ↑ method / engines / rules ↑ inputs (pinned snapshots) ↑ labels (overrides · judgments · truths) ↑ QA

Fit test. If a planner or agent can answer - (1) what we deliver and who consumes it, (2) what we read and as-of when, (3) what math/rules ran at what version, (4) what a human changed and why, (5) how a teammate re-runs this Monday - then the process fits. If they cannot, that is a readiness failure, not proof the standard is too narrow.

Escape hatch (still compliant): inputs that cannot be snapshotted use availability: external_ref + access procedure + best-effort as_of, with residual uncertainty in judgments. Silent hardcodes remain non-compliant.

5. Canonical shape

inputs (snapshots) + method (versioned guideline) → engines / transforms → outputs → labels (human deltas) → QA → MANIFEST

An Analysis Package is one bounded unit of planning work a teammate, auditor, or model could replay or learn from - not a naked workbook and not a transcript.

6. Agent contract (pair-planning)

When an agent assists a human planner, the agent MUST:

1

Open or create a package before mutating outputs.

2

Record every input read, with snapshot_id or external_ref.

3

Pin method via guideline_version + entrypoint/commit.

4

Route math through declared engines[] with deterministic: true|false.

5

Write every override to labels/ - never only into a cell.

6

Emit outputs only under output_contract paths.

7

Run QA checks; set qa.status honestly.

8

Refuse “final” if MUST fields or gates fail - return a deficiency list.

9

Stay portable - chat memory is not source of truth after the turn.

Humans may still use Sheets/Excel as UI. Agents must still materialize package exports and labels.

7. Determinism rules

LayerRule
InputsMUST be pinned (content hash and/or snapshot_id + as_of).
Deterministic enginesSame inputs + config ⇒ same outputs within declared tolerances.
Non-deterministic enginesMUST set the flag; advisory until accepted into labels/outputs.
Models / agentsMUST NOT be the only implementation of hard planning math. Drafts become labels or accepted outputs via explicit write.
Replayrepro.command SHOULD regenerate deterministic slices; document the rest.

Policy (frozen D5A): strict by default - models draft only. Pack types may opt into declared non-deterministic engines with extra QA; that is not the default.

8. On-disk layout

Authoring form is a convenience MANIFEST.yaml (and friends). Canonical envelope is an RO-Crate profile (ro-crate-metadata.json), compiled from YAML so planners and agents never hand-write JSON-LD. 

analysis_packages/<id>_<slug>_v<version>/
├── MANIFEST.yaml                 # contract instance (authoring)
├── ro-crate-metadata.json        # compiled crate (canonical)
├── GUIDELINE.md                  # method card @ guideline_version
├── inputs/                       # pinned snapshots
├── code/                         # engines / entrypoint (or immutable ref)
├── outputs/                      # artifacts + schemas
├── labels/
│   ├── overrides.jsonl
│   ├── judgments.jsonl
│   └── truths_applied.jsonl
└── qa/
    └── checks.json

9. MUST metadata (summary)

Full field table lives in the normative markdown. Core groups:

Identity & people

package_id, package_version, standard_version, title, timestamps, analyst, reviewer, agent

Contract

purpose, output_contract[] (name, consumer, format, schema, path)

Inputs & method

pinned inputs[], guideline_version, entrypoint, engines[] + deterministic flags

Labels, QA, policy

overrides/judgments/truths paths, qa.status + checks, intended use, confidentiality, training_eligibility (default false)

Pack-type profiles (e.g. commodity_commit_forecast/0.1) add typed checks and reason-code sets. They MUST NOT remove core MUST fields.

10. Labels - overrides as training gold

Hardcodes that never become rows are how token capital dies. If a number is not produced by a declared deterministic engine from pinned inputs, and not listed in labels, it does not exist for audit or training.

Override row (normative shape)

{
  "override_id": "ovr_001",
  "field_path": "supplier_forecast.ACME.BBU-100.week_36_qty",
  "before": 1200,
  "after": 900,
  "reason_code": "HOLD_FOR_PRICE_NEGOTIATION",
  "reason_text": "optional free text",
  "bucket": 3,
  "evidence_refs": ["inputs/supplier_splits.csv"],
  "author": "planner_or_agent_id",
  "ts": "2025-09-12T21:40:00Z"
}

overrides

Hard deltas with reason codes (bucket 3 or accepted corrections).

judgments

Soft overlays (bucket 2) - confidence labeled, not fake master data.

truths_applied

Planner truths/rules used this cycle (gaps the ERP still lies about).

Serialization (D4C)

Thin ap jsonl for authoring; optional Web Annotation export for interop.

11. Completeness gate

A package MAY be qa.status: approved only if machine checks pass (waivers need reasons). The validator CLI is source of truth; agents MUST invoke the same checks (D6C).

  • All MUST fields present and type-valid
  • Every output_contract entry has its artifact
  • Every file the entrypoint reads is listed under inputs or vendored in code
  • Deterministic engines are version-pinned
  • Unexplained numeric edits ⊆ labels/overrides.jsonl
  • Declared qa.checks pass or are explicitly waived

Agents MUST NOT claim the planning turn finished while the gate fails.

14. Worked example

Profile commodity_commit_forecast/0.1 - a weekly BBU/PSU-style supplier commit pack (synthetic data, real structure). 

examples/ap-example-commodity-commit-v1/
├── MANIFEST.yaml
├── GUIDELINE.md
├── inputs/          # demand, BOM, splits, inv/PO, independent demand
├── code/            # run_commit_pack.py (entrypoint stub)
├── outputs/         # supplier_forecast, exceptions, summary + JSON schemas
├── labels/          # overrides, judgments, truths
└── qa/checks.json

What it demonstrates

  • Pinned multi-source inputs with snapshot IDs (and one external_ref LTA escape hatch)
  • Three deterministic engines: explode → allocate → net
  • Labeled overrides (price hold, linearity flag, NPI bridge) with reason codes
  • Judgments and planner truths (sole-source, EOL gap)
  • Agent recorded as draft-only assist
  • output_contract consumers: sourcing managers + planning lead
  • training_eligibility false by default
  • Gate result bundle under qa/

Still stub on purpose: the Python entrypoint documents the contract and does not fully compute; content hashes are placeholders; RO-Crate compile and production ap-gate CLI are next build steps - not faked as complete.

15. Non-goals

  • One global planning algorithm or ERP replacement
  • Forbidding Excel/Sheets as interactive UI
  • Perfect master data before any package can exist
  • Storing full agent transcripts as system of record
  • Competing with Kinaxis/Anaplan as the system of record - they may emit packs
