## 11 slides (content)

### 1. Title
- Lockup + definition  
- Partner-repeatable one-liner  
- Tom Moore, founder  

### 2. Problem
- Bot proliferation inside finance  
- Management cannot see/trust bot output  
- No trace: data + method + human judgment  
- Analyst may not be human  

### 3. Solution
Unit of work = **sounding** (Analysis Package):
1. Pinned inputs, method, engines  
2. Human overrides with **credit**  
3. **Gate** before publish  
4. **Chart room** - query the validated corpus  

### 4. Why now
1. Bots already drafting in finance  
2. CI on publish unit is enforceable now  
3. LLM query/report is valuable **after** packages exist  

### 5. Insight
Producing a plan requires massive **unstructured data and judgment**.  
It will never look like a clean structured pipeline or traditional planning tool alone.  
That judgment is the product surface (labels, truths, overrides).

### 6. Competition
**Threat:** ERP ships top-down provenance and crowds budget.  
**Counter:** tailored modules already beat monoliths (Anaplan vs Oracle planning).  
fathm = bottoms-up publish contract + chart room for the AI era.

| | ERP feature | Chat/docs | Catalog | **fathm** |
|--|-------------|-----------|---------|-----------|
| Unit | suite object | threads | tables | **package** |
| Bot gate | slow | none | weak | **core** |
| Mgr query | partial | mess | wrong grain | **chart room** |
| Planner credit | buried | no | n/a | **yes** |

### 7. Product / demo
**Build target (interview demo):**
1. Publish → gate → pass  
2. Manager query / report from corpus  
3. Standard revision → HITL approve  

Flow: Standard → Gate → Store → Bots → Planner proposes → HITL.

### 8. GTM
- **ICP:** Finance team, bot sprawl, weak mgmt visibility, easy adoption  
- **Dual win:** managers (query/control) + planners (credit, less thrash)  
- **Year one:** gate + chart room (query is magic; provenance % is KPI)  
- **Objection:** "training AI to replace me" → soundings make judgment the unit of record; no cross-customer content training  

### 9. Business model
- SaaS: Standard + CI + chart room  
- Later: Planner / standard-evolution tier  
- Services only to land  
- **Pricing thesis:** benchmark Anaplan/Kinaxis-class module ACV, then ~2× for AI gate+query - **validate in pilot**  
- Not selling headcount replacement  

### 10. Traction + team
**Traction:** Spec-stage - ap/0.2, example pack, system design, brand. Pre-revenue. Honest.  
**KPI:** % published packs with full queryable provenance → 100% in pilot scope.  
**Felt win:** managers live in corpus Q&A.

## YC application answers (draft)

**Describe what your company does in 50 characters or less:**  
Provenance + chart room for AI analysis packs

**What is your company going to make?**  
Software that forces every AI- or human-published analysis into a complete Analysis Package (data, method, human judgment), gates publish, and lets managers query the team's corpus with citations - starting with finance.

**What do you understand about your business that others don't?**  
Real plans are not clean pipelines. Unstructured judgment is load-bearing. Traditional planning tools and data platforms miss the publish unit where bots now create risk. Credit for that judgment is how planners adopt.

**How far along are you?**  
Opinionated standard (ap/0.2), example package, full system design, brand. Building the UI loop: publish, manager query, standard HITL. Pre-revenue; seeking design partner.

**How will you make money?**  
SaaS subscription for standard tooling, CI gate, and chart room; upgrade path for planner/standard evolution. Implementation only to land enterprise.
